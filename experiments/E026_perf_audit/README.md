# E026: performance audit, accuracy-neutral candidates

Status: **done** (2026-10-22; RTX 4090, torch 2.14.1+cu130, code `6ae8e8c`, frozen worktree).
No library code was changed: every candidate is a runtime patch (`patches.py`) measured against
the current code. Results: `results.md` (generated by `analyse.py`), raw records in `runs/`.

## Question
A read-only audit (Codex, four per-area agents, one brainstorm) proposed ~30 changes to lower
GPU memory, host RAM or step time. Which of them pay off on real hardware, without changing
what the model computes?

## Protocol
* **Equivalence first** (`check.py`, `check.jsonl`): each patch against the current code on the
  same weights and input. float64 on CPU at an odd size (67²): relative L2 error of outputs and
  all parameter gradients ≤ 1e-9. bf16 autocast on CUDA (509²): the patched model's error
  against an fp32 run must be no larger than the current code's (10% slack). All 17
  patch × model pairs pass (float64: 0 or ~1e-15).
* **Model step** (`model_bench.py`, `run_models.sh`): forward + fp32 cross-entropy + backward,
  bf16 autocast, batch 16 at 512² (UNet++ batch 8; time series 8 × 6 dates × 13 bands at 256²),
  3 → 4 classes, random weights. Median of 40 steps after warm-up, `max_memory_allocated`. One
  process per run; current and patched runs alternate (A B A B), and Δ is the median of the
  paired ratios, so slow drift cancels (the unpaired U-Net R34 baseline drifted 84–94 ms).
* **Training loop** (`train_bench.py`): a copy of the bench trainer's inner loop with the real
  `GPULoader` (augmentation on, device-resident synthetic data), 100 timed steps, 2 reps.
* **CloudSEN12+ cold reads** (`fetch_bench.py`): the real 190 GB cache on the SATA SSD, page cache
  of the file dropped before each run, U-Net R34 13-band 512² batch 16.
* **Post-processing** (`post_bench.py`): connected components and EDT, CPU (4 threads) and CUDA.
* GPU idle apart from these runs (records carry `nvidia-smi` before/after); two 10-second
  harness smoke tests overlapped one checkpointing run.

## Results

### Same values (rounding only), clear gains
| change | where | Δ step time | Δ peak memory |
|---|---|---|---|
| Cross-attention fusion: contiguous tokens for SDPA (`_tokens`) | `fusion/ops.py` | **−50%** | **−77%** |
| SegFormer fuse: 1×1 conv per level before the upsample | `decoders/segformer.py` | −10% eager, −13 to −15% compiled | **−26 to −38%** |
| fastai_unet / U-Net `input_cross`: cast the input image to the autocast dtype before the cat | `fastai_unet.py`, `unet.py` | −10 to −13% fastai eager, −6% `input_cross`; −2% compiled | **−20%** fastai, −7% `input_cross` (−5 to −12% compiled) |
| UPerNet: bilinear outputs back to the input dtype | `decoders/upernet.py` | −5% | **−27%** |
| GroupNorm (`norm="group"`): output back to the input dtype | `layers.py` | −5% | −19% |
| Temporal mean: select and sum in bf16 with an fp32 accumulator | `temporal.py` | −3% | −13% |
| DeepLabV3+: bilinear output dtype | `decoders/deeplab.py` | ~0 | −10% |
| fastai channels_last: keep the layout through `pixel_shuffle`, in-place ReLUs | `fastai_unet.py` | −1% | −6% |

The cause of most rows: under CUDA autocast `upsample_bilinear2d`, `group_norm` and
`upsample_nearest2d` return float32 (`probe_dtypes.py`), and a `cat` with one fp32 input promotes
the whole buffer. Plain U-Net decoders are unaffected (their output stays bf16); fastai_unet,
U-Net `input_cross`, U-Net with GroupNorm, UPerNet and DeepLab carry fp32 activations today.

### Training loop (bench)
| model | each change alone | all four together |
|---|---|---|
| PVTv2-b0 SegFormer 256² | −2 to +1% | **−24%** |
| PVTv2-b0 U-Net 256² | −8 to +5% | **−26%** |
| U-Net R34 512² | within noise | −1% |
| U-Net R34 256², 13 bands (`loader` only) | −6% | |

The four: no per-batch host syncs (`isfinite` branch, `float(loss)`), `_foreach_div_`,
`AdamW(fused=True)` (rounding-level differences), and a loader without per-batch index copies or
extra fp32 temporaries (batches bit-identical to `GPULoader`'s). The gain needs all of them:
any one remaining sync still stalls the CPU every step. It matters for small, fast models
(the PVTv2 presets); large GPU-bound steps hide it.

### Memory for time (opt-in; values identical, BN running stats see a second forward)
| model | checkpointing | step time | peak memory |
|---|---|---|---|
| U-Net R34 | encoder | +5% | −22% |
| U-Net R34 | decoder (two finest blocks) | +23% | −15% |
| U-Net R34 | both | +27% | −38% |
| U-Net ConvNeXt-T | encoder | +18% | −61% |
| U-Net R34, time series | encoder | +18% | −32% |

timm's `set_grad_checkpointing` fails on ResNet out of the box ("modified by an inplace
operation"): timm's in-place ReLUs overwrite tensors the checkpoint saved. Making the encoder's
ReLUs out of place fixes it (`patches.enable_encoder_checkpointing`). Decoder checkpointing is a
poor trade.

### Inference (bf16, `inference_mode`, 512²)
| model | batch | eager | compile | compile `reduce-overhead` (CUDA graphs) |
|---|---|---|---|---|
| U-Net R34 | 1 | 4.6 ms | 1.6 ms | 1.4 ms |
| U-Net R34 | 8 | 10.6 ms | 6.1 ms | 6.0 ms |
| PVTv2-b0 U-Net | 1 | 5.6 ms | 2.6 ms | 1.5 ms |
| PVTv2-b0 SegFormer | 1 | 4.9 ms | 2.5 ms | 1.4 ms |
| PVTv2-b0 SegFormer | 8 | 8.9 ms | 5.4 ms | 5.3 ms |

CUDA graphs help at batch 1 (up to 1.8× over the default compile for the PVTv2 presets) and use
a fraction of the memory; at batch 8 they equal the default compile.

### Out-of-RAM data (CloudSEN12+)
Cold random reads run at ~360–410 MB/s (≈ 55–60 images/s at 6.8 MB each), slower than the GPU
step (~95 ms per batch of 16). A one-batch prefetch thread with pinned memory gains only 7–10%
(283–302 → 264–269 ms/step): the loop already overlaps most GPU work with the next read, because
CUDA launches are asynchronous. Training on CloudSEN12+ is disk-bound; the lever is the storage
(this machine has an NVMe drive), not the loader.

### Post-processing (identical outputs)
* Connected components with pointer jumping: 18–44× faster on long or field-like components
  (GPU and CPU), 2.2× on 512² blobs; **2× slower on small 256² blobs on CPU**, about equal on GPU.
* EDT: scipy is 11–22× faster than the torch EDT *on CPU* (max diff 1e-6), but the torch EDT on
  the GPU is already 1–10 ms, faster than scipy. Only worth it for CPU data-loader workers.

### No gain (current code stays)
* U-Net split-conv (sum of convs instead of concat-then-conv): +4% time for −5% memory; UNet++:
  +12% time for −13 to −18% memory.
* U-Net `input_cross` exact upsample under compile: −0.4%, noise.
* `pad_to_multiple` zero-pad fast path: −1%, noise.
* FPN bilinear dtype: no change (its upsampled maps are summed, not concatenated).

## Verification of the applied changes (`run_verify.sh`, `runs/verify.jsonl`)
The library on branch `perf/e026` (no patches) reproduces the patched numbers: fastai_unet
R34 8.85 GiB (patched 8.86), SegFormer R34 / PVT 2.62 / 3.35 GiB (2.62 / 3.35), UPerNet 4.24
(4.24), GroupNorm U-Net 4.08 (4.08), cross-attention 2.22 (2.22), encoder checkpointing via
`model.set_grad_checkpointing()` 2.78 (2.78).

## Round 2 candidate, negative: timm LayerNorm dtype (`ln_dtype`)
A dtype scan of whole models under CUDA bf16 autocast found timm `LayerNorm` / `LayerNorm2d`
outputs in float32, which keeps the residual stream of ConvNeXt, EdgeNeXt, PVTv2, ViT and Swin
encoders in float32. Casting the norm outputs back changes numerics (bf16 error vs fp32 +22%
on PVTv2) and buys nothing: peak memory ConvNeXt-T 6.82 → 6.82 GiB, EdgeNeXt-S 4.36 → 4.36,
ViT-S 4.89 → 4.89, PVTv2-b0 4.11 → 3.98 (−3%, −3% time), 2 pairs each. Those float32 tensors are
transient; what backward saves is already bf16. Not applied.

## Not measured
* Siamese shared-encoder batching changes BatchNorm statistics in training (out of scope:
  accuracy-neutral only); eval-only batching remains a candidate.
* Host RAM: device-resident datasets keep their numpy copies (`runner.py`, `mmap=False`);
  `io.load` builds a CPU model and a second weight copy. Code reading only.
* AMD MI250X: not run (Setonix's container is torch 2.7.1, below the 2.10 floor).
